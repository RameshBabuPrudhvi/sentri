## [Unreleased]

### Added
- **GAP-002 (audit) — Settings god-file decomposition.** The 3,595-line `frontend/src/pages/Settings.jsx` god-file is replaced with a feature-folder layout at `frontend/src/features/settings/`: a sidebar-driven shell (`SettingsLayout` + `SettingsSidebar`) backed by 9 per-section lazy chunks (`sections/account`, `sections/agent-roles`, `sections/data`, `sections/execution`, `sections/integrations`, `sections/members`, `sections/providers`, `sections/provider-routes`, `sections/security`). Each section is a bookmarkable URL (`/settings/<key>`), browser back/forward navigates between them, the sidebar `<NavLink>` lights up with `aria-current="page"`, and each section ships as its own webpack chunk so the initial Settings bundle drops materially. Industry-standard left-rail layout used by GitHub Settings / Vercel / Linear / Sentry. 7 sections (`account`, `agent-roles`, `data` + `RecycleBinGroup` + `RecycleBinPanel`, `execution`, `integrations`, `members`, `security` + `RecoveryCodesPanel` + `TotpEnrollmentPanel` + `WorkspaceMfaPolicyPanel` + `PasswordConfirmModal`) are physically extracted as discrete files; the two largest tabs (`providers`, `provider-routes` — combined ~1,600 lines) are re-exported via thin wrappers around the legacy file behind the same URL + sidebar contract while their internal decomposition is tracked as GAP-002b. Shared helpers live under `features/settings/shared/` (`SectionTitle`, `AdminLockedSection`, `DataAction`, `PasswordConfirmModal`, `formatters.js`); the section registry lives at `hooks/useSettingsSections.js` as the single source of truth for role-aware visibility + group ordering. All inline `style={{}}` blocks from the extracted components were replaced with `.st-*`, `.settings-*`, `.recycle-*`, `.members-*`, `.account-*`, `.execution-*`, `.recovery-panel__*`, `.pwd-modal__*`, `.totp-enroll__*`, `.factor-row__*`, `.passkey-item__*`, `.ws-enforce__*` classes in `frontend/src/styles/pages/settings.css` per AGENT.md §127. Legacy `/settings?tab=<key>` deep links (MfaGraceBanner → security, GitHub App install callback → integrations) continue to work via a one-shot redirect in `SettingsLayout` that preserves sibling query params.
- **DS-002 + DS-003 (audit) — Spacing and type scale tokens.** New `--space-xs|sm|md|lg|xl|2xl` (4 / 8 / 16 / 24 / 32 / 48 px) and `--text-xs|sm|base|lg|xl` (0.75 → 1.25 rem) + `--leading-tight|normal` tokens in `frontend/src/styles/tokens.css`. Locks in the de-facto sizes already scattered across the codebase as discrete, documented tokens — mirrors the Tailwind / Radix / Linear / Vercel scale. Additive only: no existing CSS consumes them yet, future components reference these tokens for visual consistency. Adoption is opportunistic — features migrate as they're touched, not a single mass rewrite.

### Accessibility
- **A11Y-001 (audit) — Global `:focus-visible` ring.** WCAG 2.4.7 (Focus Visible, Level AA) + 2.4.11 (Focus Appearance, WCAG 2.2 Level AA) compliance. Adds a 2px accent-color outline + 2px offset to every interactive element when reached via keyboard navigation (Tab, Shift+Tab, arrow keys). Mouse clicks suppress it via `:focus-visible` — no visual noise on every button press. Matches the Radix / Linear / Vercel / GitHub / Datadog convention. `.input` and `.dial-textarea` keep their existing inset box-shadow indicator (also WCAG-compliant) — the global rule is the safety net for buttons, nav links, tabs, dropdowns, and every other interactive surface that previously had no visible keyboard-focus indicator.
- **A11Y-004 (audit) — `--text3` contrast lift.** Changed `--text3` from `#9ca3af` (2.8:1 on `--bg`, failing WCAG AA at 4.5:1 for normal text) to `#6b7280` (4.6:1, passing AA). This token drives `text-muted` across timestamps, secondary labels, metadata, and hint copy — the prior contrast made meaningful text illegible for low-vision users. Dark theme is unaffected (its `--text3: #5a6378` on `#0f1117` already exceeds 4.5:1). The change is a pure visual lift; no markup or layout changes.

## [1.8.0] — 2026-05-21

### Breaking

- **Bundle 2 — `agent_configs.provider` → `routeId` migration.** Migration 048 drops `agent_configs.provider` and `agent_configs.model` columns. Dispatch now keys on `agent_configs.routeId` → `provider_routes` row exclusively. **Operators must run `node backend/src/database/migrations/scripts/backfill-routes.js` BEFORE deploying this version** — the script find-or-creates `provider_routes` rows from legacy columns and writes `routeId`. Use `--dry-run` first. Re-runnable; rows already backfilled are skipped. Per-workspace API keys are inherited from the global `apiKeyRepo` store and encrypted into each route's `apiKeyEncrypted` blob — rotate per-workspace via Settings → Provider Routes → Rotate key post-migration. `resolveProvider` is deleted; `resolveRoute` is the single dispatch path. `MODEL_PRICING` is no longer read at runtime by adapters — cost is computed by the dispatcher from `route.pricing` (operator-set) with `MODEL_PRICING` as catalog fallback. The `AI_ROUTES_ENABLED` feature flag is removed.

### Changed
- **B1.x — Per-workspace provider routes (foundation).** New `provider_routes` + `provider_route_audit` tables (migrations 035 + 036) carry one row per concrete LLM endpoint a workspace can dispatch against — protocol + baseUrl + model + encrypted API key + capabilities + pricing + per-route quotas + caching toggle + self-referential fallback chain. `agent_configs` gains an optional `routeId` column (migration 037) that pins a specific route to an agent role; when null, the legacy AI-005 `provider`-column shim path stays active so workspaces can adopt routes per-role without an all-or-nothing migration. New `backend/src/aiProvider/secrets.js` (B1.4) encrypts API keys at rest via AES-256-GCM with a `SENTRI_MASTER_KEY` master key (32 bytes base64, fail-fast in production via `ERR_MASTER_KEY_MISSING` / `ERR_MASTER_KEY_INVALID` at module load — never starts the server with a derived dev key in prod); 5-minute in-memory plaintext cache keyed by `routeId` invalidates on rotate / delete so dispatch reads decrypt at most once per 5 min. `apiKeyLastFour` is the only secret-shaped field surfaced by the default repo SELECT — ciphertext + nonce columns require an explicit `getSecretById()` call so list / render paths can't accidentally leak the blob. New `backend/src/aiProvider/adapters/protocolAdapter.js` (B1.5) is the route-driven entry point: switches on `route.protocol` (`openai | anthropic | gemini | ollama`) and delegates to four new `backend/src/aiProvider/protocols/*.js` modules that consume a resolved route directly (no env reads, no `process.env` reach-arounds). Protocol modules whose SDK doesn't expose native streaming (Gemini, Ollama in B1.5) return `null` from `stream()` and the dispatcher falls back to `generate()` + a single synthetic `onToken(text)` call so callers see the same streaming surface regardless of protocol. New `resolveRoute({ agentRole, workspaceId })` (B1.6) in `aiProvider/registry.js` returns `{ route, config, effectiveAgentRole }` via the four-step priority chain: sticky-fallback for the role > `agent_configs.routeId` > `agent_configs.provider`-column shim (synthesises a transient route id `provider:<provider>`) > workspace-default env detection. AI-005c collapse rule preserved: workspaces with no `agent_configs` row still get `effectiveAgentRole: null` so breakers / sticky / metrics use the bare-discriminator key. New `breakerDiscriminator(route)` helper strips the synthetic `provider:` prefix from transient routes so single-agent workspaces don't see their breaker state reset on the B2 dispatch flip — real routes (id `pr-<uuid>`) pass through unchanged for per-route isolation. `providerRouteRepo.upsert()` rejects `fallbackRouteId` cycles at save time with `ERR_ROUTE_FALLBACK_CYCLE` (mirrors `agentConfigRepo.wouldCreateCycle` AI-005 pattern, id-keyed instead of role-keyed, bounded at 64 hops). Every mutation appends a `provider_route_audit` row inside the same `db.transaction()` as the write — failed audit rolls back the user mutation, audit log can't drift from table state. Action variants: `create` (metadata = `{ name, family, protocol, model }`), `update` (metadata = `{ changed: [<field>…] }` via `diffFields`), `rotate_key` (any change to `apiKeyEncrypted` upgrades the action; metadata carries `{ lastFour }` ONLY — never plaintext or ciphertext, redaction is enforced by construction not by trust). Idempotent saves (no-op diff) emit zero audit rows. `remove()` nulls sibling `fallbackRouteId` references in the same tx so dispatch can rely on the invariant that every non-null fallback points at an existing row. Append-only `providerRouteAuditRepo` exposes only `append` + paginated `list` (keyset pagination via `before` cursor for O(log n) per page; `(workspaceId, createdAt)` covering index) — no update / delete paths exposed so the audit log is tamper-evident. Audit action allow-list (`create / update / delete / rotate_key / probe / export / import`) validated at append-time so typos at call sites fail fast instead of polluting the log with un-queryable variants. **B1.7 — flag-gated dispatch wiring.** `resolveAgentCall()` in `aiProvider/dispatcher.js` gains a `process.env.AI_ROUTES_ENABLED === "true"` branch that resolves a route via `resolveRoute` and returns the legacy `{ provider, config, effectiveAgentRole, ... }` shape **plus** the new `route` + `useRoutes` fields. Default off — when the flag is unset, the legacy `resolveProvider` path is byte-for-byte unchanged and the new fields are `route: null, useRoutes: false`. Flag read on every call (not cached at import) so test suites can toggle per-case without process restarts; cost is one env lookup against a hundreds-of-ms LLM call. New `backend/tests/provider-routes.test.js` (B1.3 — CRUD + cycle + JSON round-trip + audit emission with explicit "rotate_key metadata carries lastFour only, never ciphertext" assertion), `backend/tests/secrets.test.js` (B1.4 — round-trip + tamper-detect + master-key fail-fast via **subprocess spawn** since the prod-mode throw fires at module load and can't be re-triggered in-process + master-key rotation isolates ciphertexts), `backend/tests/protocol-adapter.test.js` (B1.5 — protocol switch + fail-closed on unknown + streaming-parity fallback via Ollama HTTP stub), `backend/tests/resolve-route.test.js` (B1.6 — priority chain with named numbered branches, AI-005c collapse, disabled-route returns `route: null` not silent shim, `breakerDiscriminator` namespace fix), and `backend/tests/chaos-provider.test.js` (B1.8 — Ollama protocol error injection: HTTP 500 / 401, NDJSON recovery, ECONNREFUSED retry exhaustion, pre- / mid-flight abort with listener-leak detection, opts.timeoutMs, Bearer-header forwarding).
