### Added

- **AUTO-023 Bundle 5 — Shared memory + tool calling (complete).** Closes the AUTO-023 roadmap by giving agents a thread-scoped blackboard, a closed-set tool registry with role-based visibility, server-side tool dispatch via envelopes, peer Q&A with timeout + cycle protection, and a colour-coded tool-call timeline in the UI.
  - **Thread blackboard** (migration `063_agent_thread_state.sql` + `agentThreadStateRepo`): `get` / `setKey` / `casUpdate` with optimistic concurrency (`ERR_AGENT_THREAD_STATE_VERSION_MISMATCH`, HTTP 409 semantics) and a configurable size cap (`AGENT_THREAD_STATE_MAX_BYTES`, default 64KB) that throws `ERR_AGENT_THREAD_STATE_TOO_LARGE` on breach.
  - **Tool registry** (`backend/src/aiProvider/agentTools/index.js`): closed-set of five read-only tools — `db.listExistingTests`, `db.getTest`, `crawl.getPageHtml`, `playwright.dryRun`, `thread.askPeer` — each with hand-rolled schema validation. Per-role baseline visibility intersected with `agent_configs.allowedTools` (migration `064_agent_configs_allowed_tools.sql`) so a workspace admin can narrow each role's tool surface.
  - **Tool dispatch** (`backend/src/aiProvider/agentTools/runtime.js`): the orchestrator's `executeToolCall` validates args, enforces the per-role allowlist, applies a 30s timeout (`withTimeout`), and increments `agent_tool_calls_total{tool,outcome=success|error|timeout}` on every dispatch. `tool_call` and `tool_result` envelope intents added to `agentEnvelope.INTENTS`; the orchestrator persists both via `emitAgentMessage` so the SSE snapshot + UI timeline see every round-trip.
  - **Workspace scoping enforced at the repo layer** — `db.listExistingTests` calls the real `testRepo.getByProjectId` (was a phantom `listByProject` that always returned `[]`) and verifies the project belongs to the caller's workspace via `projectRepo.getByIdInWorkspace`; `db.getTest` enforces scoping post-fetch through the test's project; `crawl.getPageHtml` checks `run.workspaceId` equality before returning page data. Agents in workspace A cannot enumerate workspace B's data even with a guessed id.
  - **`playwright.dryRun` runs the real static check** — delegates to `pipeline/testValidator.validateTest` (acorn syntax + Playwright action whitelist + assertion-chain validation + secret scan + placeholder URL rejection) instead of the regex-stub the initial scaffolding shipped. Meta-only diagnostics (no name / no steps) are filtered out so the tool's contract stays "is this Playwright code valid?" rather than "is this a complete test record?"
  - **Peer Q&A** (`thread.askPeer` / `answerPeer`): the asking agent blocks until a peer emits an `answer` envelope or `peerQuestionTimeoutMs` (default 60s) elapses. Self-asks throw `ERR_AGENT_PEER_SELF`. `MAX_PEER_NESTING=3` is enforced by a per-thread counter (pre-fix the `nesting` arg defaulted to 0 on every call and the guard was a dead branch). The orchestrator routes incoming `answer` envelopes through `answerPeer` so the round-trip works in production, not just in unit tests.
  - **Production wire-up #1 — author dedup**: `journeyGenerator.generateFromDescription` calls `db.listExistingTests` BEFORE prompt construction (when `projectId` + `workspaceId` + `runId` are all set) and appends up to 30 existing test names + sourceUrls to the LLM prompt so the author can write complementary tests instead of near-duplicates. Pre-fix the author was blind to the project's catalog and the deduplicator's post-hoc pass could only catch near-identical AI output.
  - **Production wire-up #2 — reviewer dryRun**: `feedbackLoop.runReviewerAuthorLoop`'s heuristic reviewer dispatches its check through `playwright.dryRun` so the call increments `agent_tool_calls_total{tool="playwright.dryRun"}` and surfaces in the UI timeline as a `tool_call` → `tool_result` envelope pair. Falls back to a direct `validateTest` call when the tool layer is unreachable so the reviewer never silently passes a broken test.
  - **UI tool-call timeline**: `messagesToTurns` tags every `tool_call` / `tool_result` envelope with a `_tool: { kind: "call" | "success" | "error", tool, args?, summary? }` payload. `AgentConversation.jsx` renders a dedicated `.ac-tool-row` with colour-coded `.ac-tool-chip--{call,success,error}` chips and a concise summary ("12 results", "3 issues", error message) — operators get a scannable per-thread tool timeline instead of opaque "[tool_result] Author → All — …" narration.
  - **Tests**: `agent-blackboard.test.js` (get/set/CAS + size cap), `agent-tools-registry.test.js` (schema validation, allowlist intersection, Zod structured-error contract, `limit` coercion + clamping, strict-schema unknown-arg rejection), `agent-peer-qa.test.js` (round-trip + timeout + self-cycle), `agent-tool-call-envelope.test.js` (real-validator success + failure shapes via the `playwright.dryRun` tool, rate-limit cap, abort-signal short-circuit, secret-scrubbing redaction round-trip), `agent-tools-orchestrator.test.js` (dispatch + forbidden-tool error), plus the existing `frontend/tests/AgentConversation.test.js` pinning the new `_tool` badge shape. All registered in `backend/tests/run-tests.js` / `frontend/tests/run-tests.js`.
  - **Hardening pass (gaps from post-merge review)**:
    - **Zod-backed schema validation** (`backend/src/aiProvider/agentTools/index.js`) — matches the contract `agentEnvelope.js` already uses. Errors carry `err.issues[]` with `{path, message, code}` per `ZodError.issues` so a future LLM-driven retry path can pinpoint which field needs to change without re-parsing free-text. Strict schemas (`z.object(...).strict()`) reject unknown arg keys so a typo throws instead of being silently dropped.
    - **Cross-process peer Q&A** (`backend/src/aiProvider/agentTools/runtime.js#ensurePeerBridgeSubscribed`) — `peerAnswers` Map is process-local; an answer arriving on pod B for a question issued on pod A used to be dropped. New `sentri:agent-peer-answer` Redis pub/sub channel publishes every `answerPeer()` invocation; every process subscribes and routes the answer to its local pending-Promise map. Lazy subscribe on first `askPeer` call, self-echo guard via `PEER_ORIGIN`, one-shot warn when `REDIS_URL` is unset. Matches `utils/runAbortChannel.js` (CAP-002 prior art).
    - **Per-tool rate limit** (`runtime.js#checkToolRateLimit`) — sliding-window counter per `(workspaceId, runId, tool)` over 60s. Default 60 calls/min, configurable via `AGENT_TOOL_RATE_LIMIT_PER_MIN`, hard ceiling 1000. Redis-backed (atomic INCR + EXPIRE pipeline) when available; in-memory `Map` fallback with random-sampled sweep otherwise. Fail-OPEN on Redis hiccup (same contract as `quotaGuard.checkSpendCap`). Adds `rate_limited` outcome label to `agent_tool_calls_total`. Defends against a hallucinating agent emitting hundreds of tool calls in one step (`MAX_AUTONOMOUS_STEPS=20` only caps supervisor decisions, not tool calls per step).
    - **SQL `LIMIT` pushed to DB** — new `testRepo.getRecentByProjectId(projectId, limit)` (`backend/src/database/repositories/testRepo.js`) replaces `getByProjectId` in the `db.listExistingTests` tool dispatch. A project with 10k tests used to deserialise ~10MB of JSON + boolean coercions per dedup call; the new path bounds the cost to 30 rows regardless of catalog size. `ORDER BY createdAt DESC` matches the dedup heuristic (LLM benefits most from anchoring against the most recently-written scenarios). Repo clamps `[1, 1000]` as defence-in-depth so a callsite bug can't unbound the query.
    - **`AbortSignal` propagation** — `executeToolCall` now accepts `signal` and falls back to `context.signal`; threaded into `assertNotAborted` checks between retries + at the top of the tool body, and forwarded from the orchestrator, `journeyGenerator.generateFromDescription`, and `feedbackLoop.runReviewerAuthorLoop`. A user-cancelled run no longer burns the 30s tool timeout per in-flight dispatch. Aborted calls land as `outcome=aborted` on the metric.
    - **Tool args secret scrubbing** — new `redactToolArgsForPersistence(tool, args)` (`runtime.js`) runs the existing CAP-003 `secretScanner` across `playwright.dryRun.testCode` (the only free-form-string arg in the registry today). When findings exist, `testCode` is replaced with a `[REDACTED — N secrets detected]` placeholder and `_secretsScrubbed` stamps the matched rule ids. Raw `testCode` still flows through `executeToolCall` for the real dryRun (so the validator still sees the original); only the persisted envelope (the `agent_messages.artifact` JSON column + SSE timeline) sees the scrubbed form. Wired into orchestrator dispatch + `feedbackLoop.js` reviewer envelope emit; `db.listExistingTests` args (structured ids, no free-form text) pass through unchanged.
    - **Bounded retry on transient failures** (`runtime.js`) — idempotent reads (`db.listExistingTests`, `db.getTest`, `crawl.getPageHtml`, `playwright.dryRun`) retry up to 2× on `SQLITE_BUSY` / `SQLITE_LOCKED` / `ECONNRESET` / `ETIMEDOUT` / `EAI_AGAIN` / "database is locked" / "connection refused" / "timed out". Exponential backoff with jitter (100ms × 2^attempt + ≤50ms). `thread.askPeer` is excluded — re-broadcast would double-resolve the pending Promise. `AbortError` + `ERR_AGENT_TOOL_FORBIDDEN` + validation errors are NEVER retried. Successful-after-retry dispatches surface as `outcome=success_after_retry` on the metric.
    - **`tool_result` envelope summary unification** (`backend/src/aiProvider/agentOrchestrator.js#summarizeToolResult`) — orchestrator now emits the summary form (`{ count | ok | issueCount | found | hasHtml }`) matching the contract production wire-ups in `journeyGenerator.js` + `feedbackLoop.js` already use. Raw tool output stays in the in-process `thread[]` for supervisor routing decisions; the persisted envelope is compact so a 30-element test array no longer balloons the `agent_messages.artifact` JSON column.
